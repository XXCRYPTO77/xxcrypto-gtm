## Dark theme rules — USE CoinW TOKEN SYSTEM

F has already set up the dark theme infrastructure. The ArenaBoard wrapper uses the `.cw-dark` CSS class, which overrides all semantic CSS variables to dark values. **This is defined in `src/styles/tokens.css`.**

**What `.cw-dark` does:**
- `--color-page` → `#0B0B0F` (dark bg)
- `--color-surface` → `#16161D` (card bg)
- `--color-ink` → `#FFFFFF` (text)
- `--color-muted` → `rgba(255,255,255,0.5)` (secondary text)
- `--color-border` → `rgba(255,255,255,0.08)` (borders)
- `--color-brand` → `#7C5CFF` (brighter purple for dark bg)
- All `--cw-green`, `--cw-red`, etc. → brightened for dark bg readability

**How to use in components:**

```tsx
// ✅ CORRECT — use CSS variable references or Tailwind token classes
<div className="bg-[var(--color-surface)] text-[var(--color-ink)] border-[var(--color-border)]">
<span className="text-[var(--color-muted)]">subtitle</span>
<span className="text-cw-green">+18.4%</span>   // functional colors auto-adapt inside .cw-dark
```

```tsx
// ❌ WRONG — hardcoded colors
<div className="bg-[#0D0D14] text-white border-white/10">
<span className="text-white/60">subtitle</span>
```

**Why this matters:**
- Hardcoded colors break if we ever tweak the dark palette — token changes propagate everywhere
- CoinW design system compliance requires all colors through tokens
- Glassmorphism `backdrop-blur` cards: use `bg-[var(--color-surface)]` with optional `/80` opacity modifier

**The `.cw-dark` wrapper is already in `boards/Arena/index.tsx`.** You just need to make sure all new components inside it use `var(--color-*)` references, not hardcoded hex values.

**Functional colors (涨跌色):** Inside `.cw-dark`, `text-cw-green` / `text-cw-red` automatically use brightened values. No manual override needed.

**Glass card recipe:**
```tsx
className="rounded-2xl border border-[var(--color-border)] bg-[var(--color-surface)]/80 backdrop-blur-xl"
```
